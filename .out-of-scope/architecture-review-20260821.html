1. Replace authorial theater with a readable collection

Strong

The current handoff says “quiet,” but the implementation still asks the typography, orbit, grain, poetic copy, paper surface, and artwork to perform personality at the same time. The result is journal-like and hard to read.

Files

LandingPage.tsx
styles.css
practice-map.css
portfolio-redesign-handoff.md

Problem

The landing module has a large visual interface — hero metaphor, orbit, grain, serif display type, editorial labels, cards, and about note — but no single readable hierarchy.

Solution

Deepen the landing module around one job: identify the collection and let a visitor choose a project. Use a highly legible display/sans pairing, a restrained surface, plain copy, and one quiet motion cue. Remove anything that does not improve finding or understanding the work.

Wins

  • locality: hierarchy lives in one module
  • leverage: every project benefits from the same readable card
  • tests hit title, description, and link behavior
  • fewer visual decisions to re-litigate

2. Deepen one motion policy module

Strong

Pointer, scroll, reset, and reduced-motion behavior is repeated across the landing module, project artwork, Code Layout, and the old spatial prototype. Every visual direction can therefore drift into its own “tasteful” motion language.

Files

LandingPage.tsx
ProjectArtwork.tsx
CodeLayoutPage.tsx
PortfolioPrototype.tsx
styles.css / prototype.css

Problem

The motion interface is spread over imperative event handlers and CSS variables. Reduced-motion rules exist in several implementations, so restraint is a convention rather than a local invariant.

Solution

Create one deep motion module at the seam between interaction state and visual styling. It owns pointer capability, bounded tilt, scroll reveal, reset behavior, and the reduced-motion decision; surfaces only the small state the landing and project modules need.

Wins

  • locality: one reduced-motion policy
  • leverage: one bounded response everywhere
  • the interface is the test surface
  • prototype motion cannot silently redefine production rules

3. Stop project modules from knowing CSS geometry

Worth exploring

`ProjectPresentationPart` exposes class names, anchor coordinates, scatter coordinates, z-depth, and rotation. The project-owned contract is a real seam, but its interface currently leaks the implementation of the artwork renderer.

Files

contracts/project-presentation.ts
projects/*/project.ts
shell/src/shell/ProjectArtwork.tsx
styles.css

Problem

Changing art direction or typography requires editing project descriptors because semantic identity and renderer geometry share one interface.

Solution

Keep project modules responsible for meaning — artifact kind, labels, and the few parts that matter — and let the deep artwork module derive placement, material, and motion from that recipe. Two real project adapters justify this seam.

Wins

  • smaller interface for project authors
  • locality: art direction changes in one module
  • leverage: new projects avoid coordinate tuning
  • tests assert meaning, not pixels

4. Retire the old spatial prototype from the shipped shell

Worth exploring

The default route changed, but `App`, `PortfolioPrototype`, `prototype.css`, the comparison query aliases, and the historical handoff still keep two visual systems alive. The old implementation is useful evidence, but it is now a competing source of truth.

Files

App.tsx
prototype/PortfolioPrototype.tsx
prototype/prototype.css
portfolio-redesign-handoff.md

Problem

The deletion test says the comparison route can disappear without removing a user-facing project capability. Keeping it expands the visual implementation and makes future reviews ambiguous.

Solution

Archive the prototype as design evidence outside the shipped shell, then make the current landing module the only production visual source. Preserve the handoff as history, not as a route users can mistake for the product.

Wins

  • deletion test passes cleanly
  • locality: one visual source
  • smaller production bundle
  • less design drift

Top recommendation

Start with “Replace authorial theater with a readable collection.”

It addresses the user-visible failure first: the font and surface are asking to be admired instead of helping a visitor read. Once the landing module has a clear typographic hierarchy, the motion policy and artwork seam can be judged against a stable interface rather than used to compensate for it.
