## Checklist — what a kept summary must contain

KEEP (the durable spine):
- Final verdict/decision state — adopted / rejected / pending — including pending→adopted transitions (both states if the trail matters).
- Quality-gate result (tsc/build/probe pass|fail) — usually already in meta; don't duplicate.
- Lesson or hard constraint born in this node (e.g. a ban list, a camera lesson).
- Open thread / explicit next-step, only if unresolved as of the checkpoint.
- Durable pointers (brief filename, doc-anchor, commit sha) are already in `artifacts` — do not restate them in prose.

DROP (reconstructable or duplicated):
- Step-by-step narration of implementation passes (what file changed in what order).
- Owner mood/color commentary — unless the quote itself is the decision (then keep it in one clause).
- Rationale duplicated in a linked doc or in meta.
- Enumerations restatable from the referenced brief.
- "Nothing committed / keep-delivery-separate" boilerplate — collapse to a `verdict: pending` fact.
