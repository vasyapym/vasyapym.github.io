# The Same Address

A chess program keeps the starting position in a constant. `start` is an array of eight ranks, each an array of eight squares, each square a letter for a piece or an empty string. A game begins with `let board = start;`, and every move after that is played on `board`: one square emptied, another filled. The button marked New Game assigns `start` to `board` again.

On Tuesday the first game opens with the king's pawn, two squares forward, and then New Game. The pawn stays on e4. Reloading the page sends it home, which is the clue: the script that builds `start` runs once, on load, so between loads the starting position of chess has a pawn on e4. Nothing in the program assigns to `start`. It is a `const`. The only line that writes anything writes to `board`.

Here is what `let board = start` did. When the script loaded, the engine built nine arrays — eight ranks and the one that holds them — set them down somewhere in memory, and gave `start` not the outer array but where it is: its address. The second line copied that address into `board`, and nothing else. There was never a second board. A variable holds either a value or the address of an object; two variables can hold the same address, which is why changing "one" changes "the other" — and why `const` only stops you from re-pointing the variable, not from changing what it points at.

So New Game copies the address of `start` into `board`, which already holds it, and the board is set to itself. And `const` kept its word throughout: `start = []` would have thrown a TypeError on the spot. The variable is guarded. The nine arrays at the other end of the address were never its business.

The usual repair is `let board = [...start];`, and it is half a repair. The spread builds a new outer array, at a new address, and copies eight things into it — and the eight things are addresses. Each rank is still the one rank, shared between the new board and the old, and the pawn moves on both. A copy like this is new on the outside only; the word for it is shallow, and `Object.freeze` is shallow in the same way — one array frozen, the eight behind it as writable as before.

`structuredClone(start)` follows every address it finds and builds a fresh object at the end of each. Every browser has had it since March 2022; before that, people sent the object through JSON and back, and got their dates returned as strings.

A function's parameter is one more variable. Hand `board` to `play(board, from, to)` and the function receives the address, can move a piece the whole program will see, and cannot make the caller's `board` point anywhere else. Barbara Liskov's group at MIT, designing CLU in the seventies, named the arrangement call by sharing. The name never travelled far. The arrangement is in every browser.

What the squares hold is the other kind of value. `'P'` is a string, and a string is not something a slot points at; the slot holds the string itself. Copy the slot and, as far as anyone can tell, there are two of them, and nothing in the language can alter either one — `toLowerCase` hands back a new string and leaves the old as it was. Numbers, booleans, `undefined`, `null` and two rarer kinds are the same, seven in all: none can be changed, only replaced, which is why they can safely be handed around as themselves. Everything else — arrays, functions, dates, anything built with braces — is an object, lives somewhere, and is known by its address.

`===` has known this all along. Given two strings it compares the strings. Given two objects it asks one question — same address? — and has no interest in what is inside. While the bug was live, `board === start` was true. After `structuredClone` it is false, though the two boards agree on every one of the sixty-four squares. They are two boards. New Game has somewhere to go.
