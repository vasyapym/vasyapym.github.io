# The Reader
Someone writing a test for an invoice types amount: '12.50', and before the line is finished there is a red underline beneath amount, and behind it a sentence: Type 'string' is not assignable to type 'number'.

Nothing has run; the file has not been saved. Something read the line as it was typed, as text, and held it against another file, invoice.ts, where an amount is declared to be a number.

invoice.ts is a JavaScript file with types written into it. A function called total adds up the amounts in a list of lines; after its parameter the author has put : Line[], after the closing parenthesis : number, and a few lines up, under the name Line, what a line is: a description, a string; an amount, a number. Everything else in the file is JavaScript as it stands; a .js file renamed .ts is already a TypeScript file with no types written in yet.

The reader is the TypeScript compiler — in the editor, reading over the author's shoulder; at the command line, called tsc. It holds each type against every use it can see and says where they disagree. '12.50' has quotes, so it is a string; amount was declared a number; they cannot both be right, and it says so, under the word. It has no view on whether 12.50 is the price of stamps. The author deletes the quotes and the underline goes.

When the file is finished, tsc reads it once more and writes invoice.js beside it. It would have written it with the quotes still in — objecting and writing are separate jobs, joined only by a flag called noEmitOnError — but the quotes are gone and it has nothing to say. The function in invoice.js begins function total(lines) {. The types are not in it — not shortened, not encoded, not in it. TypeScript is a reader, not a runtime: it reads the program before it runs, argues about what could go wrong, and then removes every trace of itself — the JavaScript that actually runs has never heard of the types.

So the browser that loads invoice.js cannot check that an amount is a number: the word number is not in the file it was given. The check happened once, earlier, on a text the browser will never see.

In production the lines come from a server, as JSON, and the author has declared the parsed result a Line[] — accepted without argument, because what a server will send is not written anywhere the reader can read. Should the server one day put its amounts in quotes, the program will add the strings end to end, the invoice will say £012.503.00, and nothing will object: the declaration that called the amount a number is not in the program that is running.

The reader does not claim otherwise. Its designers kept a list of what it would not try to be; the third item is a sound, "provably correct" type system — in its place, "a balance between correctness and productivity".

It was shown on the first of October 2012 by Anders Hejlsberg, at Microsoft, who had made Turbo Pascal, Delphi and C#. Among the goals its designers wrote down are "impose no runtime overhead" and a type system that is "fully erasable": the program that runs was to be the program that would have run anyway.

There is one exception, and it is famous. enum Direction { Up, Down } cannot simply be removed, because the program will ask for Direction.Up at run time and expect an answer. So the compiler writes into the JavaScript a small object, in a few lines of its own, one of which reads Direction[Direction["Up"] = 0] = "Up"; — code that came from TypeScript rather than through it. A few relatives behave the same way; together they are the whole of what it leaves behind.

Since January 2025 Node has run .ts files directly, without checking the types. It finds where each one begins and ends and overwrites it with spaces: : Line[] becomes eight spaces, : number eight more, the declaration of Line a blank patch the same height. No source map is made, because nothing has moved. It cannot do this to an enum, which needs something in its place rather than nothing, and says so and stops. TypeScript 5.8, that February, added a flag called erasableSyntaxOnly, under which the reader refuses the enum before Node has to, so that what reaches Node can be erased without being read.
