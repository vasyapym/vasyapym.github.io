# It Never Guesses

A page keeps count of how often it has been opened. The script is three lines: read the old count out of the browser's storage under the key `visits`, add one and show it, write it back. Storage keeps nothing but strings; hand it a number and it stores the digits.

On the first visit there is no such key, and storage hands back `null` to say so. The engine arrives at `visits + 1` holding `null` on the left and `1` on the right, and does not stop to consider what the author meant. It has a rule for `+`, and the rule opens with a question: is either side a string? Neither is. Then both become numbers, and in the table the engine uses for that, the row for `null` says zero — not a view about `null`, just the row. Zero and one make one. The page shows 1, and storage writes it down as the string `'1'`.

On the second visit the left side is that string. Is either side a string? Yes. Then the other side becomes a string too and the two are joined: `'1'` next to `'1'` is `'11'`. The page shows 11. The third visit shows 111, the fourth 1111, and the engine has been exactly as diligent each time. One thousand one hundred and eleven is four.

JavaScript never guesses: when it meets two things of different types it follows a short, fixed rulebook, and the results people call weird are the rulebook working exactly as written. `+` has one preference, strings, because it does two jobs — adding and joining — and needs a rule to choose between them; the rule is that a string on either side means joining. Every other arithmetic sign has one job, wants numbers, and makes numbers of the strings, booleans and nothings it is handed: `'111' - 1` is `110`.

The counter's repair is `Number(visits) + 1`. `Number` is the conversion the minus sign performs, asked for by name. `'111'` becomes 111, and `null` still becomes 0, so the first visit still counts as one; it always did.

There is another nothing, and the engine keeps them apart. `null` is nothing that someone put there on purpose: storage returned it to say "no such key", and a program sets a field to `null` to say "empty, and I know it". `undefined` is what the engine itself hands over when nothing was ever put there — a variable declared and not yet assigned, a field nobody set, a function that returned without saying what.

The table has a different row for it. Keep the count in a field of an object instead, forget to give it a starting value, and adding one to it gives `NaN`. The deliberate nothing counts as zero. The accidental one does not count as a number at all, which is what `NaN` says. The engine has not confused the two once.

`typeof` converts nothing; it reports what kind of value it was given, and for `undefined` says `'undefined'`. For `null` it says `'object'`. In the first implementation every value carried a small tag in its lowest bits saying what kind it was; objects had tag zero, and `null` was stored as the zero pointer, so its tag read as object. A correction was proposed for the 2015 standard and turned down, since by then pages depended on the answer. It is the one row nobody chose.

Two equals signs have a rulebook of their own, three rules long. If both sides are the same type, they are compared as they stand, the way three equals signs would compare them. If not, `null` and `undefined` are equal to each other and to nothing else — not to zero, not to the empty string, not to `false` — which is why `visits == null` is the line that catches both nothings at once. What remains, strings and numbers and booleans in any mixture, is compared as numbers: the empty string equals `0` because its row in the table says zero, and `'0'` equals `false` because both of their rows do. The operator is not malfunctioning. It is reading the same table as the minus sign.

An `if` reads a different table, and that one is short. Eight values count as false: `false`, `0`, `-0`, `0n`, the empty string, `null`, `undefined` and `NaN`. So `if (visits)` sends the first visit, which is `null`, down the false branch, and sends a stored `'0'`, a string with a character in it, down the true one. Everything not on the list counts as true — an empty array, an empty object, and the string `'false'`, which the engine sees as five characters and does not read.
