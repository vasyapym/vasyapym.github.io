# Where It Was Written

A file called `cache.js` is five lines long. It makes a `Map` called `store` and a counter called `hits`, and it hands out three functions: `get`, which reads the map and adds one to the counter; `set`, which writes the map; and `report`, which returns the counter. Node loads the file at startup. The run takes less than a millisecond, top to bottom, and then it is over in the ordinary sense: those five lines will not run again.

Three weeks later the process is still up, `get` is still finding the map, and `report` returns a number in the millions. It returns the number `hits` holds now, not the zero it held when the file ran. Had `get` been handed a copy of `hits` at startup, it would have spent three weeks adding one to a private zero, and `report`, with a copy of its own, would still say zero.

Node, as it happens, does not run a file as a file. It wraps the text in a function and calls it:

`(function (exports, require, module, __filename, __dirname) { `

Every file Node has loaded as a CommonJS module — which, for its first decade, was every file — has been the body of that function. So `store` and `hits` are not globals, and not properties of anything. They are local variables of a function call that returned three weeks ago.

A function keeps a reference to the place it was created, and can still see the variables there long after that place has finished running. When a call begins, the engine makes a record of that call's variables — one for this run; the next run gets its own. A function written during the run is given, along with its code, a reference to that record: not the values in it, the record.

When the call returns, the record is not thrown away. Nothing in JavaScript is thrown away because a call returned; things go when nothing can reach them, and three functions can reach this one. That is the whole of why `report` says millions: `get` and `report` hold the same record, and `hits` is one slot in it. There is one `hits`, and it is where it was written.

The same fact, with three functions in one place, is the loop beginners are told is a bug. `for (var i = 0; i < 3; i++) later.push(() => i)` writes three small functions during one run of the enclosing function, and `var` gives that run one `i`. The loop finishes; `i` is 3. The three functions are called; each looks up `i` where it was written, and finds 3.

Written with `let` in the head of the loop, the same line yields 0, 1, 2, and the reason is in the standard under a name of its own, CreatePerIterationEnvironment: before each pass the engine makes a new record and copies the counter into it. Three passes, three records, three functions, each holding the one it was written in.

For most of the language's life this was also its only privacy and its only module system. There were no modules until 2015 and no private fields until 2022, so a variable that only certain functions should see was put inside a call, the functions were written there, and the call returned. Crockford described the pattern for objects in 2001; browser scripts wrapped themselves in a function and called it on the spot; Node made the wrapping automatic in 2009, which is the line above. The map in `cache.js` cannot be reached from outside the file except through its three functions, and nothing had to be declared private for that to be so.

The record is kept whole. A function holds the entire record of the place it was written, not only the variables it mentions, and so does every other function written there, for as long as any one of them is reachable. Suppose a function parses an eighty-megabyte file into `rows`, and two small functions are written inside it: a tooltip that reports `rows.length`, and a resize handler that reads only the filename. The tooltip is gone in a minute. The resize handler lives as long as the window, and so do the eighty megabytes, because what it holds is the place, not the names it used. The memory profiler will show a one-line arrow function retaining a large array it never mentions, and the profiler is right.

`cache.js` ran in under a millisecond, three weeks ago, and is finished. The place it ran in is not: a map, a counter, and three functions holding its address, until the process ends.
