# Orchestrate declarations — the common block (one file for every machine)

The orchestrator reads declarations from `~/.config/orchestrate/declarations.md`
on each machine. That file has two parts, in this order:

1. **The common block** — the lines below, identical on every machine. Copy
   them into the machine's declarations file; adopt updates by pulling this
   repository.
2. **The project lines** — each project keeps its own below the common block
   (models, paths, obsidian and briefs folders, byte-check and integration
   modes, per-round notes). Our project-specific declarations are added to
   this file too, as they settle.

## Common block

collapsed paste: eaten line breaks are never guessed back in the main session; the restore attempt is briefed to Sonnet 5.5 — a chat model like the Creative relay — with the collapsed bytes and the byte-authoritative originals carried in the brief; a raw-file export from the chat stays the preferred path when it exists.

sonnet 5.5: takes about 60 KB per brief; split longer relays by deliverable.

TD (reply carriage): TD means the traktorodetal.ru project — the spares/Bitrix catalog work — when the user names TD for the session or brief, every artifact to be placed is carried as ONE physical line — every break written as the marker character the brief dictates (⏎ has served) — and the orchestrator decodes it mechanically after the cut; without TD the reply shape is the standard marker-line contract with no carriage.

creative (reply carriage): a creative usually writes in one line anyway — we can simply ask it to write the reply that way: ONE physical line, every break the marker character (⏎ has served), decoded mechanically after the cut; no project name needed.
